# 赛季切换

赛季是 HopliteRoyale 长线运营的节奏。一个赛季通常 3 个月,期间战令积累,赛季结束**进度归档,外观保留**。

## 赛季是什么

| 字段 | 说明 |
| --- | --- |
| 赛季 ID | 数字编号,1 / 2 / 3 |
| 赛季名 | 显示名,如 "第一赛季:荣耀初现" |
| 开始 / 结束日期 | YYYY-MM-DD |
| 每阶经验 | 升一阶需要的战令经验 |
| 每阶奖励 | 免费 + 进阶双轨各一份 |

## 默认赛季表

| 赛季 | 时间 |
| --- | --- |
| 第一赛季:荣耀初现 | 2026-05-01 ~ 2026-07-31 |
| 第二赛季:边境回响 | 2026-08-01 ~ 2026-10-31 |

可在 `plugins/HopliteRoyale/battlepass/season-N.yml` 自由扩展。

## 自动切换

主配置里:

```yaml
season:
  auto-switch: true
```

开启后,插件**按日期自动**:

1. 检测当前日期是否进入新赛季的 `start` ~ `end` 区间
2. 把上个赛季玩家进度归档到历史表
3. 重置当前赛季进度
4. 加载新赛季的奖励配置
5. **保留**所有玩家已获得的外观

## 手动切换流程(谨慎)

如果你想**提前**结束赛季 / **延后**开新赛季:

1. **备份数据库**
2. 修改对应 season 的 `start` / `end` 日期
3. 重启服务器(让赛季配置重新加载)
4. 验证 `/bp season` 显示正确
5. 验证 `/bp progress` 不会反向丢数据
6. 公告玩家

::: warning 不要随意修改已结束赛季的配置
已经发出的奖励、记录里的快照已经写库。改老赛季配置不会回滚已发奖励,只会让 GUI 显示混乱。
:::

## 切换前自检清单

新赛季上线**前一周**完成:

- [ ] 新赛季 `season-N.yml` 已写好
- [ ] 每阶奖励都有效(`COINS` 数额合理,`COSMETIC` ID 真实存在)
- [ ] 测试服把日期手动调到新赛季,验证:
  - [ ] `/bp season` 显示新赛季
  - [ ] `/bp` GUI 渲染正常
  - [ ] `/bp claim all` 能领第 1 阶免费奖励
  - [ ] 升级到 Lv2 触发奖励解锁
- [ ] 已经获得的外观**没有丢失**
- [ ] 公告 / 资源包(如有)同步上线

## 切换日当天

```text
1. 备份生产数据库
2. 在低峰时间段重启服务器
3. 启动后立刻 /bp season 验证
4. 找一个老玩家测试 /bp progress(应显示重置)
5. 找一个老玩家测试 /cosmetic(已获得的应保留)
6. 全服公告:新赛季开启
```

## 数据归档

每个赛季结束,玩家进度会迁移到归档表(具体表名见 `db/migration`)。这意味着:

- 你随时可以做赛季排行榜回顾
- 玩家**当前赛季**的进度从 0 开始
- 历史最高等级 / 总参与场次等"长期统计"会保留(如果配置启用)

## 推荐节奏

| 节奏 | 适合 |
| --- | --- |
| 3 个月 / 赛季 | 大型综合服(默认) |
| 1 个月 / 赛季 | 高强度小游戏服 |
| 2 周 / 赛季 | 公会内部赛 / 短期活动 |

赛季越短,**奖励曲线要越平**——不然玩家追不上。

## 常见问题

**Q1. 玩家进度被错误重置了?**  
99% 是赛季配置 `start` / `end` 日期写错了。检查时区(配置默认 UTC)。

**Q2. 老外观看不见了?**  
`cosmetic_ownership` 表跨赛季保留。如果没了,检查表里那条记录是否被误删。

**Q3. 下个赛季还没准备好,但日期到了?**  
临时改 `auto-switch: false`,然后准备好后再开回来 + 重启。
